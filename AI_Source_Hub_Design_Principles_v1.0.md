# AI Source Hub Design Principles v1.0

## 1. Mission

AI Source Hub creates practical AI products that solve real business problems.

We do not create prompt collections, generic AI tools, or educational content disguised as products. We create focused AI decision engines that help users get a useful business result quickly.

Every AI Source Hub product must help a user make progress on one specific business problem.

## 2. Vision

AI Source Hub will become a trusted library of small, practical AI products for entrepreneurs, operators, freelancers, and business builders.

Each product should feel like a fast expert assistant built for one job:

- Validate an idea
- Improve an offer
- Clarify a customer
- Diagnose a business problem
- Choose a next action
- Turn messy input into a practical business output

The long-term vision is not to build one large, complex platform. The vision is to build a connected system of simple, useful AI products that help users make better business decisions with less confusion.

## 3. Core Principles

### 1. One Product, One Problem

Each product must solve one clear problem only.

If a product tries to solve multiple problems, it should be split into smaller products.

### 2. Results Over Explanations

The user comes for an outcome, not a lesson.

The product should give the user a decision, score, diagnosis, recommendation, draft, checklist, or action plan before offering explanation.

### 3. Usable Within 2 Minutes

The user should understand what to do almost immediately.

The first usable action should be obvious without onboarding, tutorials, or long instructions.

### 4. Useful Within 10 Minutes

The product should deliver meaningful value quickly.

For most products, the user should be able to enter basic information and receive a practical output in under 10 minutes.

### 5. Fewer Questions, Better Questions

Every input field is a cost to the user.

Only ask for information that directly improves the output. If an input does not change the result, remove it.

### 6. Measurable Value

Every feature must create measurable value.

Examples of measurable value:

- Saves time
- Improves a decision
- Reduces uncertainty
- Clarifies the next step
- Produces a usable business asset
- Increases confidence in a specific action

### 7. Build Step By Step

Products should start narrow.

We add complexity only after the simple version proves useful.

## 4. Product Design Philosophy

AI Source Hub products should behave like focused business tools, not open-ended chatbots.

The user should not need to know how to prompt, structure a request, or manage a conversation. The product should guide the user through a short path and produce a useful result.

### Product Shape

Each product should have:

- A clear problem
- A clear user
- A small number of required inputs
- A defined evaluation or transformation method
- A structured output
- A recommended next action

### Product Experience

The ideal experience is:

1. User enters a small amount of information.
2. Product evaluates or transforms that information.
3. Product returns a clear result.
4. User knows what to do next.

### Product Boundaries

A product should not expand just because AI can do more.

The correct question is not "What else can AI generate?"

The correct question is "What is the smallest useful result this user needs right now?"

## 5. User Experience Rules

### Start With The Task

The first screen should let the user begin the task.

Avoid:

- Long welcome screens
- Abstract product descriptions
- Multi-step onboarding
- Feature tours before value

### Make The Primary Action Obvious

Each product should have one main action.

Examples:

- Validate Idea
- Analyze Offer
- Score Landing Page
- Generate Action Plan
- Improve Positioning

### Keep Inputs Minimal

Use the fewest fields needed to produce a useful result.

Inputs should be plain-language and easy to answer.

### Accept Imperfect Input

Users often do not know the perfect answer.

Products should accept "not sure", vague drafts, and incomplete thinking, then reflect uncertainty in the output.

### Return Structured Outputs

Outputs should be easy to scan.

Use:

- Verdicts
- Scores
- Short summaries
- Tables
- Prioritized risks
- Single next actions

Avoid long paragraphs unless the product specifically requires writing.

### Always Give A Next Action

Every output should answer:

"What should I do next?"

The product should provide one best next action, not a list of ten possibilities.

### Do Not Overwhelm The User

Complexity should be hidden unless it improves the result.

The product may use advanced reasoning internally, but the user experience should remain simple.

## 6. Writing Style

AI Source Hub writing should be direct, practical, and calm.

The tone should feel like a sharp business advisor who respects the user's time.

### Style Rules

Write with:

- Short sentences
- Plain language
- Clear recommendations
- Specific observations
- Direct labels
- Practical next steps

Avoid:

- Hype
- Motivational filler
- Academic language
- Long explanations
- Generic business advice
- Excessive disclaimers
- Overly friendly chatbot language

### Preferred Output Language

Use decisive words when the product has enough information.

Examples:

- "Pursue"
- "Improve"
- "Pause"
- "Biggest risk"
- "Next action"
- "Score"
- "Weakest area"
- "Recommended path"

### Explanation Standard

Explanations should be short and tied to the result.

The user should never have to read a long explanation to understand the decision.

## 7. AI Behavior Rules

The AI inside each product must behave like a focused decision engine.

### The AI Must

- Stay within the product's defined purpose.
- Use the required framework for evaluation.
- Produce structured outputs.
- Give one clear recommendation when possible.
- Penalize vague or missing inputs rather than inventing certainty.
- State uncertainty when information is incomplete.
- Prefer practical actions over abstract advice.
- Keep the user's business goal in focus.

### The AI Must Not

- Act like an open-ended chatbot.
- Generate unrelated business advice.
- Expand the task without user need.
- Ask many follow-up questions.
- Invent market facts, competitor claims, revenue numbers, or customer evidence.
- Produce long reports when a short decision would be more useful.
- Make the user responsible for interpreting the result.

### Handling Missing Information

When information is missing, the AI should:

1. Continue if a useful result is still possible.
2. Lower the relevant score or confidence.
3. Explain the gap briefly.
4. Recommend the best next action to close the gap.

The AI should not block the user unless the missing information makes the product impossible to use.

## 8. What We Never Build

AI Source Hub should not build products that violate the core philosophy.

### We Never Build

- Prompt packs
- Generic chatbot wrappers
- Products with no clear business outcome
- Tools that require users to understand prompting
- Bloated dashboards with unclear value
- Products that ask many questions before giving value
- Products that produce long generic reports
- Products that pretend to validate facts without evidence
- Products that create complexity instead of reducing it
- Products that solve multiple unrelated problems at once

### We Avoid

- Feature creep
- Vague productivity tools
- AI novelty products
- "All-in-one" business assistants
- Outputs that sound impressive but do not help the user act

## 9. Product Quality Standards

Every AI Source Hub product must meet the following standards before release.

### Clarity

The product must clearly state what it does.

The user should understand the purpose within seconds.

### Speed

The user should be able to start using the product within 2 minutes.

The product should produce a useful result within 10 minutes for the core use case.

### Focus

The product must solve one problem only.

Additional features should support that problem, not expand the product into a different job.

### Output Quality

The output must be:

- Structured
- Specific
- Actionable
- Easy to scan
- Connected to the user's input

### Decision Quality

If the product gives a recommendation, it must explain the basis for that recommendation briefly and consistently.

The recommendation should follow defined logic, not random AI judgment.

### User Effort

The product should require the least effort possible from the user while still producing a useful result.

Unnecessary fields, steps, settings, and explanations should be removed.

### Measurable Value

The team should be able to define how the product creates value.

Examples:

- Time saved
- Better decision made
- Risk identified
- Output generated
- Next action clarified
- User confidence improved

## 10. Definition Of An AI Decision Engine

An AI Decision Engine is a focused AI product that helps a user make a specific decision or take a specific next action using structured input, defined evaluation logic, and a clear output.

It is not a general chatbot.

It is not a prompt.

It is not a content generator with a nice interface.

It is a productized decision system.

### Required Parts Of An AI Decision Engine

An AI Decision Engine must include:

1. A specific business decision or problem
2. A defined target user
3. Minimal required inputs
4. A clear evaluation framework
5. Consistent scoring or reasoning logic
6. A structured result
7. A recommendation or next action
8. Boundaries that prevent unrelated outputs

### Example

Business Idea Validator is an AI Decision Engine because it:

- Solves one problem: evaluating a business idea
- Uses four required inputs
- Scores the idea across defined criteria
- Produces a verdict
- Identifies the biggest risk
- Recommends one next action

### Decision Engine Standard

If a product cannot clearly answer "What decision does this help the user make?", it is not ready to be built.
